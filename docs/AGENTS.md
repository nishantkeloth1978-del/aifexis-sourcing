# AI agents (Phase 4: event drafter)

**Harness** (`src/agents/harness.ts`): every agent call goes through `runAgent`: Claude with the company's own key only (free models are never used), fixed prompt, JSON answer validated against a schema, one retry with the reason when the answer is bad, a daily cap per company (Configuration → Automation → "AI drafts per day", default 50), and a stored `agent_run` (digest of the input, validated output, model, tokens, state). Failure is a stored `failed` run and a message telling the buyer to create the event by hand. Nothing an agent returns changes business data by itself.

**Drafter** (`src/agents/drafter.ts`): on a new request, a buyer chooses **Draft with AI**. The proposal (title, items with specification/section/material group, notes to confirm) appears on the request page, editable. **Create draft event from this** is gate 1: it creates an ordinary draft event (marked `drafted_by_agent`, audit entry names agent and run) which still needs the normal approval before publication. **Discard** closes the proposal. A reload shows the waiting proposal without another call.

**Rules the model is held to** (checked in code, not trusted): every quantity must be one the request stated (or 1 when it had no lines); the required date can only be the request's needed-by date; item and field limits are the same as for a hand-made event. The requester's text is passed inside a `<request>` data block and the prompt tells the model to ignore instructions in it; even if it obeys, the checks above reject the result (tested with an injection fixture).

**Not yet:** category/template-driven questions and criteria (events in this system take those from templates and company configuration), lots, timeline suggestions, agent usage by type on a report. Bid reader and recommender (phases 5 and 6) reuse the same harness.

Migration: 0060_agent_run.sql

**Recommender** (`src/agents/recommender.ts`): on the commercial panel, once the comparison is open and every evaluation assumption is filled, the buyer chooses the supplier (or one per lot) and selects **Draft the reason with AI**. Input is a `<facts>` block built in code from the stored comparison. The answer ({note, points}) is checked: every number must appear in the facts (single digits allowed), the note must name the chosen supplier, no links or markup. Flags are computed in code and shown beside the draft with the exact figures the AI was given. The text only fills the reason box; recording the recommendation and the award approval are unchanged. Buyer only; counts against the daily AI cap.


**Automatic first draft** (`src/agents/autodraft.ts`, migration 0066): Configuration > Automation > "Draft every new request with AI automatically" (off by default; needs autonomy level 2 and the company's own Claude key). When a request is saved (form or API; an API connection set to create events straight away is not drafted) the drafter runs right after the answer is sent, stores a proposal on the request page and notifies the buyers. A buyer reviews it and clicks **Create draft event from this** (gate 1); publication and award approval are unchanged. A request is drafted once (a failed run is not repeated; a buyer can still use Draft with AI by hand). A backup sweep in the automatic run drafts up to 2 requests per pass that are over 3 minutes old and still without a draft (restarts, time-outs, file imports). Every run counts against the daily AI cap.

## Level 3: Autopilot
Settings, Automation: level 3 lets the system run an eligible request with no person approving. Per request it needs: an AED estimated value at or below the Autopilot limit, an award policy needing one approver, request lines carrying a material group, and at least the minimum number of active suppliers whose Category equals that group. Then three system identities (buyer, witness, approver; `@autopilot.invalid`, never shown in lists or notified) create the event, publish it for the configured days, and invite those suppliers. After closing it opens envelopes, qualifies bidders on mandatory pass/fail gates only (no technical scores), runs the bid check, ranks, recommends and approves the award. It holds, and tells buyers, on too few bids, any warn/block bid-check finding, a close result, missing assumptions or lots. Everything is logged as "Autopilot". An administrator can take an event over from the event page. Setting the level below 3 stops it.
